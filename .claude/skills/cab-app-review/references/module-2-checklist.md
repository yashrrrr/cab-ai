# Module 2 — Application Change Requests

Source of truth — copied verbatim from the CAB Readiness Agent brief. Rows
3, 6, and 10 are conditional (see SKILL.md for the applicability check).

| # | Validation Area | Mandatory Approval / Document | Required Approver / Stakeholder |
|---|---|---|---|
| 1 | Architecture Review | Architecture review and approval. | Shinu Arjunan |
| 2 | Data Privacy Alignment | Data Privacy review and alignment. | Data Privacy Team |
| 3 | AI Architecture Alignment | AI Architecture review and approval (if AI components are involved). | AI Architecture Team |
| 4 | Security Validation | VAPT Report (Vulnerability Assessment and Penetration Testing). | Security Team |
| 5 | Testing Validation | Test Cases and Test Sign-Off Documents. | Testing / Business Sign-Off Team |
| 6 | Vendor Involvement | SOP documentation when vendor applications or vendors are involved. | Relevant Vendor / Delivery Team |
| 7 | Security Assessment | ISMS Security Impact Assessment Report. | ISMS / Security Team |
| 8 | Business & Design Documents | BRD, FRD, Flow Diagrams, Architecture Diagrams, and Network Architecture Diagrams. | Project Team |
| 9 | Integration Approval | Service Owner approval emails for application integrations. | Respective Service Owners |
| 10 | Cloud Subscription Hosting | Approval required if the application is hosted in another team's cloud subscription. | Cloud Subscription Owner |
| 11 | Change Justification | CR Description must clearly include Business Justification, Problem Statement, Proposed Solution, Expected Outcomes, and Stakeholder/Consumer Impact. | Requestor |
