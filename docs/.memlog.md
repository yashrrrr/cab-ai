- (event) Legacy brief (docs/brief.md, status Ready-for-PM-review) has no .memlog.md; this update is its first entry. No PRD/architecture/stories exist yet downstream, so no ripple beyond the brief.
- (change) Change signal: introduce multi-stage CAB gated by environment (Dev CAB -> QA CAB -> Prod CAB), where a later stage requires the prior stage's CAB id to initiate.
- (assumption) Source doc (UST Change Mgmt v6.1) Section 11.0/12.0/14.0 describes weekly CAB, ad-hoc CAB, ECAB (emergency), pre-CAB, and ARB -- no environment-staged CAB concept exists in the source. This is a net-new, user-driven requirement, not source-traced -- conflicts with brief's stated principle that every rule traces to the source doc.
- (decision) Model correction: NOT one RFC passing through 3 sequential CAB approval gates. Instead each RFC carries an environment mode (Dev/QA/Prod); a QA-mode RFC requires a related Dev-mode RFC to exist; presumably Prod-mode requires a related QA-mode RFC. Applies across all 5 change types per user.
- (decision) Confirmed: Standard changes ARE included in env staging (QA-mode Standard RFC requires a related Dev-mode Standard RFC in Approved state). Gate is creation-time: QA RFC cannot be opened/created without the approved predecessor. 'environment' is a new field orthogonal to 'type' -- does not replace it. No new 'business change' super-entity: each RFC is independently user-created; the environment field + predecessor-linkage is the only mechanism.
- (decision) Final rule set: (1) Emergency is EXEMPT from environment-staged gating entirely (speed/retrospective-logging nature). (2) Standard, No Impact, Normal, Expedited are all gated. (3) Gate mirrors Dev->QA->Production: QA-mode RFC requires a related Dev-mode RFC of the SAME type in status=Completed (fully implemented+validated), and Production-mode RFC requires a related QA-mode RFC of the same type in status=Completed. (4) This SUPERSEDES the earlier looser statement of 'approved state' -- the real gate is Completed, not merely approved/in-progress. (5) 'environment' is a new field orthogonal to 'type' -- type-specific approval mechanics (auto-approve/2-tier/CAB/ECAB) unchanged. (6) No new CAB board membership per environment -- same reviewers per type, environment is a tag/precondition, not a new approval body.
